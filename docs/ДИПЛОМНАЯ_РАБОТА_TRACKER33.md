## 1. ВВЕДЕНИЕ

Современный рынок труда характеризуется растущими требованиями к эффективности использования рабочего времени. Особенно актуальна эта проблема в IT-сфере, где результат работы часто носит интеллектуальный характер и сложно поддается прямому измерению. Традиционные методы учёта рабочего времени, основанные на ручном заполнении табелей или простом контроле времени присутствия, не отражают реальной продуктивности сотрудников.

**Актуальность темы** обусловлена необходимостью создания автоматизированных решений для точного учёта рабочего времени с возможностью анализа продуктивности различных видов деятельности. Существующие коммерческие решения либо имеют высокую стоимость, либо не учитывают специфику конкретных организаций.

**Цель работы**: разработать информационную систему автоматического учёта рабочего времени с возможностью классификации активности по критериям продуктивности.

**Задачи исследования**:

1. Проанализировать существующие подходы к учёту рабочего времени
2. Выбрать оптимальный технологический стек для разработки
3. Спроектировать архитектуру информационной системы
4. Реализовать серверную часть на базе Django REST Framework
5. Разработать клиентское приложение для автоматического отслеживания
6. Протестировать систему и оценить её эффективность

**Объект исследования**: процессы учёта и анализа рабочего времени в организациях.

**Предмет исследования**: методы автоматизации учёта рабочего времени с использованием современных информационных технологий.

## 2. ОСНОВНАЯ ЧАСТЬ

### 2.1. Теоретическая часть

#### 2.1.1. Анализ современных подходов к учёту рабочего времени

Существующие методы учёта рабочего времени можно классифицировать по следующим критериям:

**Таблица 1. Классификация методов учёта рабочего времени**

| Критерий                              | Ручной учёт    | Полуавтоматический | Автоматический      |
| --------------------------------------------- | ------------------------ | ------------------------------------ | --------------------------------- |
| Точность                              | Низкая (60-70%)    | Средняя (80-85%)              | Высокая (95-98%)           |
| Трудозатраты                      | Высокие           | Средние                       | Минимальные            |
| Возможность анализа         | Ограниченная | Базовая                       | Расширенная            |
| Сопротивление персонала | Низкое             | Среднее                       | Возможное высокое |

Анализ показал, что наиболее перспективным является автоматический подход с элементами интеллектуального анализа активности пользователя.

#### 2.1.2. Преимущества и недостатки различных методов

**Ручные методы** (табели, отчёты) имеют следующие недостатки:

- Субъективность данных
- Высокая трудоёмкость ведения
- Невозможность детального анализа
- Склонность к округлению и приблизительности

**Автоматические системы** обладают преимуществами:

- Объективность получаемых данных
- Высокая детализация информации
- Возможность выявления паттернов продуктивности
- Минимальные трудозатраты на ведение учёта

Основной недостаток автоматических систем - необходимость обеспечения баланса между детальностью контроля и приватностью сотрудников.

## 3. ПРАКТИЧЕСКАЯ ЧАСТЬ

### 3.1. Реализация системы

#### 3.1.1. Описание компонентов

**Серверная часть реализована на Django со следующей структурой**:

```python
# tracking/models.py - Основные модели данных
class Application(models.Model):
    user = models.ForeignKey(CustomUser, on_delete=models.CASCADE)
    name = models.CharField(max_length=255)
    process_name = models.CharField(max_length=255)
    is_active = models.BooleanField(default=True)
    is_productive = models.BooleanField(default=False)

class UserActivity(models.Model):
    user = models.ForeignKey(CustomUser, on_delete=models.CASCADE)
    application = models.ForeignKey(Application, on_delete=models.CASCADE)
    start_time = models.DateTimeField()
    end_time = models.DateTimeField()
    duration = models.DurationField()
    keyboard_presses = models.IntegerField(default=0)
```

**Ключевые особенности реализации моделей**:

- Автоматическое вычисление длительности при сохранении
- Индексы для оптимизации запросов по пользователю и времени
- Каскадное удаление связанных записей
- Очистка кэша при изменении данных

**API реализовано через Django REST Framework**:

```python
# tracking/views.py - API endpoints
class UserActivityViewSet(viewsets.ModelViewSet):
    queryset = UserActivity.objects.all()
    serializer_class = UserActivitySerializer
    permission_classes = [permissions.IsAuthenticated]

    def get_queryset(self):
        return UserActivity.objects.filter(user=self.request.user)
```

**Клиентская часть построена на архитектуре с разделением обязанностей**:

```python
# desktop_app/main.py - Основной класс приложения
class TimeTrackerApp(QMainWindow):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.tracking_active = False
        self.api_client = None
        self.activity_queue = queue.Queue()
        self.current_activity_data = {}
      
    def setup_activity_listeners_and_tracking_timer(self):
        # Настройка слушателей клавиатуры и мыши
        self.keyboard_listener = keyboard.Listener(
            on_press=self.on_keyboard_press
        )
        self.mouse_listener = mouse.Listener(
            on_move=self.on_mouse_move,
            on_click=self.on_mouse_click
        )
```

**Основной алгоритм отслеживания активности**:

1. **Инициализация слушателей** - запуск мониторинга клавиатуры и мыши
2. **Таймер основного цикла** - проверка активного окна каждую секунду
3. **Определение приложения** - получение процесса активного окна
4. **Сравнение с предыдущим состоянием** - выявление смены приложения
5. **Завершение/начало сессии** - корректное оформление периодов активности
6. **Подсчёт активности** - накопление статистики по нажатиям клавиш
7. **Отправка данных** - периодическая синхронизация с сервером

### 3.4. Инструкция по эксплуатации

**Системные требования**:

**Сервер**:

- ОС: Linux Ubuntu 20.04+ или Windows Server 2019+
- RAM: минимум 2 ГБ, рекомендуется 4 ГБ
- Свободное место: 10 ГБ
- Python 3.9+

**Клиент**:

- ОС: Windows 10+, Linux Ubuntu 18.04+, macOS 10.15+
- RAM: 512 МБ
- Свободное место: 100 МБ
- Права администратора для установки

**Установка сервера**:

```bash
# 1. Клонирование репозитория
git clone https://github.com/user/tracker33.git
cd tracker33

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Настройка базы данных
python manage.py migrate

# 4. Создание суперпользователя
python manage.py createsuperuser

# 5. Запуск сервера
./start_server.sh
```

**Установка клиента**:

```bash
# 1. Переход в директорию клиента
cd desktop_app

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Запуск приложения
python main.py
```

**Первоначальная настройка**:

1. **Настройка сервера**:

   - Укажите URL сервера в формате `http://server:8001`
   - Введите учётные данные пользователя
   - Проверьте соединение кнопкой "Проверить соединение"
2. **Настройка отслеживания**:

   - Выберите приложения для отслеживания
   - Отметьте продуктивные приложения
   - Настройте интервал отправки данных (по умолчанию 10 секунд)
3. **Запуск отслеживания**:

   - Нажмите кнопку "Начать отслеживание"
   - Приложение свернётся в системный трей
   - Проверьте корректность работы через веб-интерфейс

**Рекомендации по эксплуатации**:

- Регулярно обновляйте список продуктивных приложений
- Настройте автозапуск клиента с системой
- Проводите еженедельный анализ статистики для выявления трендов

```python
# tracking/models.py (фрагмент)
class UserActivity(models.Model):
    user = models.ForeignKey(CustomUser, on_delete=models.CASCADE)
    application = models.ForeignKey(Application, on_delete=models.CASCADE)
    start_time = models.DateTimeField()
    end_time = models.DateTimeField()
    duration = models.DurationField(null=True, blank=True)
    keyboard_presses = models.IntegerField(default=0)
  
    def save(self, *args, **kwargs):
        if self.start_time and self.end_time and (self.duration is None):
            self.duration = self.end_time - self.start_time
        super().save(*args, **kwargs)
```

**Б.2. API клиент для взаимодействия с сервером**

```python
# desktop_app/api_client.py (фрагмент)
class APIClient:
    def __init__(self, base_url: str):
        self.base_url = base_url.rstrip('/')
        self.session = requests.Session()
        self.token = None
      
    def authenticate(self, username: str, password: str) -> bool:
        response = self.session.post(
            f"{self.base_url}/api/token/",
            json={'username': username, 'password': password}
        )
        if response.status_code == 200:
            self.token = response.json().get('token')
            self.session.headers.update({
                'Authorization': f'Token {self.token}'
            })
            return True
        return False
```
